# AIM 경량화 스터디 — 8주 커리큘럼

> 기존 노션의 논문 리뷰와 스터디 기록을 바탕으로 재구성한 커리큘럼이다. 지식 증류 → 프루닝 → 양자화 → 작은 모델 설계 → 실행 최적화 순서로 학습하고, 마지막 주에는 직접 측정한 결과를 발표한다.

## 1. 구성 배경

학술 연구팀 노션의 ‘경량화’ 데이터베이스와 연결된 자료를 확인했다. 아래는 **기록에서 확인한 내용**이며, 주차 배치·실습·운영 시간·평가 기준은 이번 커리큘럼을 위해 새로 제안한 내용이다. 리뷰 페이지의 존재와 실제 발표·실습 완료 여부는 구분한다.

| 스터디 기록표: 9/12 OT 및 기본 논문 선정, 9/26 논문 2편 리딩·토론, 11/7 CUDA 기초 | 논문 리딩·토론 방식을 유지하고, 공통 실습과 CUDA 세션을 추가 구성 |

기록표의 날짜에는 연도가 명시되어 있지 않아 월·일만 인용했다. 본 커리큘럼은 기존 내용을 8주 과정으로 다시 운영하는 안이며, 기존 참여자는 개념 복습을 짧게 하고 실험과 원문 검증에 시간을 더 배정한다.

## 2. 대상과 운영 방식

- **대상:** Python·PyTorch로 간단한 모델 학습이 가능하고, 역전파·CNN·softmax를 이해하는 학부생 수준.
- **기간:** 8주, 주 1회 2시간 모임 + 개인 준비·실습 2~4시간. 장시간 학습이 필요한 경우 사전 학습 체크포인트를 공유한다.
- **모임 구성:** 지난 결과 공유 15분 → 논문·개념 발표 35분 → 코드·실험 리뷰 40분 → 토론 20분 → 다음 과제 정리 10분.
- **역할:** 발표자·실습 담당·기록 담당을 순환한다. 모든 참여자는 사전 질문을 1개 이상 준비한다.
- **공통 실습:** CIFAR-10과 작은 순차형 CNN을 사용한다. Teacher와 채널 수가 작은 Student를 준비하고, 1~4주차 결과를 최종 프로젝트까지 누적한다.
- **자원 조정:** CPU만 있는 팀은 1주차에 MNIST와 더 작은 CNN으로 확정한다. CUDA 실습은 NVIDIA GPU가 있는 팀원의 시연·측정 결과를 함께 분석하거나 CPU 프로파일링 과제로 대체한다.
- **LLM 범위:** AWQ·BitNet은 작은 텐서와 계층으로 원리를 확인하는 실습을 기본으로 한다. 전체 LLM 양자화·추론은 지원 장비와 실행 환경이 확보된 팀의 선택 과제로 둔다.

## 4. 주차별 상세 계획

### 1주차 — 경량화 개요와 기준 모델 측정

**목표:** 경량화의 목적을 정확도·저장 용량·메모리·지연 시간으로 구체화하고, 이후 실험에서 사용할 비교 기준을 만든다.

**학습 내용**

- 지식 증류, 구조적·비구조적 프루닝, 양자화의 차이.
- 파라미터 수, MACs/FLOPs, 모델 파일 크기, 실행 중 메모리, latency, throughput.
- 정확도와 자원 사용량의 trade-off, 비교 조건을 고정해야 하는 이유.

**실습**

1. 데이터셋과 Teacher·Student 구조를 확정하고 학습 또는 검증된 체크포인트를 준비한다.
2. 학습·검증·테스트 데이터를 구분하고, seed·전처리·학습 예산을 기록한다.
3. Teacher와 단독 학습 Student의 정확도, 파라미터 수, 파일 크기, 추론 시간을 측정한다.
4. 공통 결과표와 측정 함수를 만들어 이후 주차에서 재사용한다.

**산출물:** `baseline.md`, 기준 체크포인트, 벤치마크 코드.

**토론:** 파라미터 수가 절반이면 추론 시간도 절반이 될까?

**자료:** [PyTorch Knowledge Distillation 튜토리얼의 모델·데이터 구성](https://docs.pytorch.org/tutorials/beginner/knowledge_distillation_tutorial.html), [PyTorch Profiler](https://docs.pytorch.org/tutorials/recipes/recipes/profiler_recipe.html).

### 2주차 — Knowledge Distillation

**목표:** Teacher의 출력 분포를 활용해 작은 Student의 성능을 개선하고, Student를 작게 만드는 설계와 증류의 역할을 구분한다.

**필수 논문:** [Distilling the Knowledge in a Neural Network](https://arxiv.org/abs/1503.02531).

**학습 내용**

- Hard target과 soft target, dark knowledge, temperature의 역할.
- 정답에 대한 교차 엔트로피와 Teacher–Student 분포 간 KL divergence의 결합.
- 증류 손실의 `T²` 보정, Teacher 고정, 평가 시 temperature 처리.

**실습**

1. 1주차와 같은 Student 구조에 지식 증류를 적용한다.
2. 단독 학습과 KD의 Student 초기 가중치·데이터·학습 예산을 맞춘다.
3. Temperature는 `T=1, 4`부터 비교하고, 여유가 있으면 손실 가중치를 바꾼다.
4. Teacher / Student 단독 학습 / Student+KD의 성능과 비용을 비교한다.

**산출물:** 증류 학습 코드, 학습 곡선, 세 모델 비교표.

**토론:** 같은 Student라면 증류 전후 추론 비용은 왜 대체로 같을까? Teacher가 틀린 샘플에서는 어떤 일이 생길까?

### 3주차 — 필터 단위 구조적 프루닝

**목표:** 필터를 제거하는 기준과 계층 사이의 연결 관계를 이해하고, 실제 텐서 크기가 줄어드는 모델을 만든다.

**필수 논문:** [Pruning Filters for Efficient ConvNets](https://arxiv.org/abs/1608.08710).

**학습 내용**

- L1-norm에 따른 필터 중요도, 계층별 민감도, 재학습을 통한 정확도 회복.
- 필터 제거에 따른 다음 계층 입력 채널·BatchNorm 등 관련 요소의 수정.
- 0으로 마스킹하는 방식과 계층을 작은 크기로 재구성하는 방식의 차이.

**실습**

1. 1주차 기준 CNN의 대상 계층을 정하고 L1 기준으로 필터를 정렬한다.
2. 대상 계층의 필터를 `20%, 40%` 제거한 모델을 각각 만든다.
3. 프루닝 직후와 동일 예산으로 미세조정한 뒤의 성능을 비교한다.
4. 파라미터·연산량 감소와 실제 latency 변화를 함께 기록한다.

**산출물:** 실제 채널 수가 줄어든 모델, 비율별 비교표, 민감한 계층에 대한 해석.

**토론:** 기존 리뷰에서 제기한 “L1-norm은 왜 유효한 기준인가?”를 실험으로 확인한다. 선택 과제로 무작위 필터 제거와 비교한다.

### 4주차 — Dynamic Model Pruning with Feedback

**목표:** 학습 중 마스크를 바꾸고 제거된 가중치를 재활성화하는 과정을 이해한다.

**필수 논문:** [Dynamic Model Pruning with Feedback](https://arxiv.org/abs/2006.07253).

**학습 내용**

- 고정 마스크, 점진적 프루닝, 동적 프루닝의 차이.
- DPF의 핵심: 희소 가중치에서 계산한 기울기를 유지 중인 dense 가중치에 적용하고 마스크를 갱신하는 과정.
- 3주차의 구조적 프루닝과 이번 주의 가중치 단위 희소화가 해결하는 문제의 차이.

**실습**

1. 논문의 Algorithm 1을 따라 가중치·마스크·기울기 갱신 과정을 의사코드로 정리한다.
2. 작은 CNN에서 고정 마스크와 DPF를 같은 초기화·최종 희소도·학습 예산으로 비교한다. 기본 목표 희소도는 `50%`로 둔다.
3. 마스크 갱신 시 다시 활성화되는 가중치의 수와 검증 정확도를 기록한다.
4. 단순히 `weight * mask`를 사용해 제거된 위치의 기울기가 차단되는 구현과 DPF의 차이를 확인한다.

**산출물:** 갱신 규칙 설명, 학습 곡선, 마스크 변화 기록.

**토론:** 희소 모델의 정확도가 좋아져도 범용 dense 연산에서 추론 속도가 빨라지지 않을 수 있는 이유는 무엇일까?

**원문 확인 포인트:** 노션의 여러 요약을 논문의 알고리즘과 대조한다. DPF의 feedback을 단순한 ‘계층별 기울기 크기에 따른 프루닝 비율 배분’으로만 설명하지 않도록 한다.

### 5주차 — 양자화 기초와 AWQ

**목표:** 양자화 오차의 원리를 이해하고, 활성화 정보를 이용한 스케일링이 출력 오차에 미치는 영향을 확인한다.

**필수 논문:** [AWQ: Activation-aware Weight Quantization for LLM Compression and Acceleration](https://arxiv.org/abs/2306.00978). 첫 독해에서는 방법론인 3절을 중심으로 읽는다.

**학습 내용**

- Scale·zero-point·clipping, 대칭·비대칭 양자화, per-tensor·per-channel·group-wise 양자화.
- PTQ와 QAT, weight-only 양자화와 `W4A16` 표기.
- Calibration 데이터, 활성화 통계, 중요 채널을 보호하는 AWQ의 스케일링.
- Fake quantization으로 오차를 확인하는 단계와 실제 저비트 저장·커널 실행 단계의 차이.

**실습**

1. 작은 가중치 행렬에서 8비트·4비트 양자화와 역양자화를 구현한다.
2. 고정된 선형 계층과 입력에 대해 기본 양자화의 출력 오차를 측정한다.
3. 별도의 calibration 입력으로 활성화 통계를 구하고, 채널 스케일링을 적용한 뒤 같은 평가 입력에서 오차를 비교한다.
4. 기본 실습은 **AWQ 원리를 확인하는 축소 실험**으로 명시한다. 전체 AWQ 재현은 선택 과제로 진행한다.

**산출물:** 비트 수·스케일링 방식별 출력 오차 표, calibration과 평가 데이터 구분 기록.

**선택 실습:** [AWQ 공식 구현](https://github.com/mit-han-lab/llm-awq)이 지원하는 모델·장비에서 실제 INT4 모델의 메모리·품질·속도를 측정한다. 기준 모델과 동일한 토크나이저·평가 텍스트를 사용한다.

**토론:** 가중치의 크기만 볼 때와 활성화까지 볼 때 중요 채널의 판단이 어떻게 달라질까?

### 6주차 — BitNet b1.58과 작은 모델 설계

**목표:** 초저비트 학습과 재귀적 모델 설계를 비교하며, ‘작은 파라미터 수’와 ‘적은 실행 비용’을 구분한다.

**필수 논문:** [The Era of 1-bit LLMs: All Large Language Models are in 1.58 Bits](https://arxiv.org/abs/2402.17764).

**확장 세미나:** [Less is More: Recursive Reasoning with Tiny Networks](https://arxiv.org/abs/2510.04871). 모두 초록·핵심 구조·결론을 읽고, 담당 발표자가 TRM의 반복 계산과 실험 범위를 설명한다.

**학습 내용**

- BitNet b1.58의 삼진 가중치 `{-1, 0, 1}`, BitLinear, 저비트 학습과 STE의 역할.
- `log₂(3) ≈ 1.58`이라는 표현량과 실제 저장 형식·스케일·기타 텐서 비용의 차이.
- AWQ의 학습 후 양자화와 BitNet의 학습 단계부터 반영하는 설계의 차이.
- TRM의 가중치 재사용과 반복 추론: 반복 횟수에 따른 총 연산량·latency도 함께 고려한다.

**실습**

1. 작은 Linear 계층의 가중치를 삼진화하고 복원 출력과 원본 출력의 차이를 확인한다.
2. FP32 텐서에 삼진 값만 넣은 구현의 파일 크기를 측정하고, 이론적 비트 수와 비교한다.
3. KD / 프루닝 / AWQ / BitNet / TRM을 적용 시점·재학습 필요 여부·실행 조건으로 비교한다.

**산출물:** 초저비트 원리 노트북, 다섯 접근법 비교표, TRM 논문 결과를 해석할 때 필요한 비교 조건.

**토론:** 작은 모델을 여러 번 실행하는 것이 큰 모델을 한 번 실행하는 것보다 언제 유리할까?

**선택 실습:** [BitNet 공식 추론 프레임워크](https://github.com/microsoft/BitNet)의 지원 환경에서 공개 모델을 실행한다. 작은 계층 실습의 결과를 전체 LLM 품질이나 실제 저비트 가속의 재현으로 해석하지 않는다.

### 7주차 — CUDA 기초와 실제 성능 분석

**목표:** 기존 스터디의 CUDA 기초 주제를 경량화 실험과 연결하고, 실행 시간을 좌우하는 병목을 찾는다.

**자료:** [NVIDIA CUDA Programming Guide](https://docs.nvidia.com/cuda/cuda-programming-guide/), [PyTorch Profiler](https://docs.pytorch.org/tutorials/recipes/recipes/profiler_recipe.html).

**학습 내용**

- Thread·block·grid, host와 device, global/shared memory의 기본 개념.
- GPU 비동기 실행과 시간 측정, CPU–GPU 전송 비용, kernel launch 비용.
- Compute-bound와 memory-bound, 연산량 감소와 실측 속도 개선의 관계.

**실습**

1. NVIDIA GPU 환경에서는 벡터 덧셈 예제로 thread와 메모리 접근을 확인한다.
2. 기준 CNN과 2~3주차의 경량 모델을 프로파일링하고 시간이 많이 드는 연산을 찾는다.
3. 지원되는 정밀도 변경 또는 데이터 전송 방식 개선 중 한 가지를 적용한다.
4. 동일 장비·batch size에서 정확도와 실행 시간을 다시 측정한다. GPU가 없으면 CPU에서 연산별 시간과 batch size 영향을 분석한다.

**산출물:** 프로파일링 결과, 주요 병목 설명, 개선 전후 비교표.

**프로젝트 준비:** 최종 비교 모델과 평가 조건을 확정하고 추가 실험을 시작한다.

### 8주차 — 통합 프로젝트와 최종 발표

**목표:** 재현 가능한 실험으로 방법의 효과와 한계를 설명하고, 주어진 배포 조건에 적합한 모델을 선택한다.

**기본 프로젝트 — 이미지 분류 모델 경량화**

1. 1주차부터 사용한 같은 데이터셋에서 Teacher, 단독 학습 Student, KD Student, 구조적으로 프루닝한 모델을 비교한다.
2. 선택 과제로 프루닝한 모델을 KD로 미세조정한다. 일반 미세조정과 동일 예산으로 비교해 조합의 추가 효과를 확인한다.
3. 정확도–latency 또는 정확도–파일 크기 그래프를 만들고 목표 조건에 맞는 모델을 선택한다.

**선택 프로젝트 — LLM 양자화**

- 실행 환경을 미리 확보한 팀은 같은 원본 모델의 기준 정밀도와 실제 AWQ 양자화 결과를 비교한다.
- 평가 품질, 모델 파일 크기, peak memory, prefill과 decode 성능을 기록한다.
- 전체 추론을 수행하지 못했다면 계층 단위 오차 분석으로 범위를 명시하고 결과를 보고한다.

**최종 제출물**

- 실행 방법·환경 버전·설정·seed가 포함된 코드와 README.
- 기준 모델과 변형 모델의 비교표, 최소 1개의 trade-off 그래프.
- 방법 선택 이유, 개선된 항목, 악화된 항목, 실패 사례를 담은 2~4쪽 보고서.
- 팀별 10분 발표와 5분 질의응답. 팀 수에 따라 세션 시간을 조정한다.

## 5. 공통 측정·기록 기준

아래 조건은 논문의 결과를 그대로 재현했다는 주장보다, 팀 내 비교가 공정하고 다시 실행 가능한지를 확인하기 위한 기준이다.

| 항목 | 기록 기준 |
| --- | --- |
| 평가 품질 | 분류는 accuracy, 언어 모델은 고정 평가 텍스트의 perplexity 또는 정해진 과제 지표. 서로 다른 데이터셋·지표를 한 순위로 비교하지 않는다. |
| 파라미터·희소도 | 전체 파라미터 수와 0이 아닌 파라미터 수를 구분한다. 마스킹만 적용했는지 실제 구조를 줄였는지도 표시한다. |
| 모델 크기 | 실제 배포용 저장 파일의 크기를 측정한다. optimizer 상태가 포함된 학습 체크포인트와 구분한다. |
| 연산량 | 입력 크기와 MACs/FLOPs 계산 규칙을 함께 적는다. 이론적 연산량으로 실측 속도를 대신하지 않는다. |
| 실행 메모리 | 장비·batch size·정밀도와 측정 방법을 적는다. 모델 가중치, activation, LLM의 KV cache가 영향을 준다. |
| Latency | 같은 장비·입력·batch size에서 평가 모드와 gradient 비활성화를 적용한다. 워밍업 후 반복 측정하며 GPU는 적절히 동기화한다. |
| 측정 범위 | 모델 연산만 잰 값과 데이터 전송·전처리를 포함한 값을 구분한다. LLM은 입력·생성 길이를 고정하고 prefill/decode를 구분한다. |
| 데이터 사용 | 하이퍼파라미터 선택에는 검증 데이터를, 양자화 통계에는 calibration 데이터를 사용한다. 최종 테스트 데이터는 튜닝에 사용하지 않는다. |
| 반복과 예산 | 일상 실습은 고정 seed로 시작한다. 최종 학습 비교는 가능하면 3개 seed를 사용하고, 부족하면 단일 실행임을 명시한다. 시간 측정은 워밍업 20회·측정 100회를 출발점으로 삼아 장비에 맞게 조정한다. |
